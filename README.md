# Relational Databases for Data Science — Homework 1

Домашня робота з проєктування реляційної бази даних для ML-сценарію на основі **MovieLens 100K**.

Основна мета роботи — побудувати нормалізовану схему PostgreSQL, додати історичне зберігання ознак і показати коректне формування навчальних даних за принципом **Point-in-Time correctness**.

## Що реалізовано

- ER-модель предметної області;
- DDL для PostgreSQL 16;
- нормалізація бізнесових таблиць до 3НФ;
- зв'язки N:M через окремі зв'язувальні таблиці;
- історичне зберігання ознак через `valid_from` / `valid_to`;
- окрема таблиця актуальних ознак для швидкого доступу;
- `VIEW` для зручного представлення оцінок разом із жанрами;
- формування навчальних подій;
- AS-OF запити для вибору правильної історичної версії ознак;
- перевірка перетинів часових інтервалів;
- демонстрація витоку даних при неправильному `JOIN`.

## Point-in-Time correctness

Історичні версії ознак зберігаються на інтервалах:

```text
[valid_from, valid_to)
```

При формуванні навчальних даних використовується лише та версія ознак, яка була чинною в `prediction_ts`.

Це запобігає потраплянню майбутніх даних у навчальні ознаки та дозволяє уникнути data leakage.
